# Catalog::counters copies the write path's counter-page setup

## Report

`Catalog::counters` (`crates/adtb/src/catalog/mod.rs:855-886`, added by log-grant-rows) allocates the page of id counters, advances each relation whose single key is generated by `sequence` past the largest key its key index holds, and names the page. `write::Database::new`'s `sequences: None` branch (`crates/adtb/src/write/mod.rs:516-537`) does the same allocation and advance. Engine open now always passes `Some(catalog.counters(..))` (`crates/adtb/src/api/mod.rs:582`, `:631`), so only `adtb-sim/tests/calls.rs:865` and `constraints.rs:633` still reach the write-path copy. The two choose relations by different tests: `rel.key.len() != 1` against `!r.single_key`. A counter page made by one can differ from one made by the other.

Fix: make `Setup::sequences` a `Pid`, have the two sim tests call `Catalog::counters`, and delete the `None` branch.
