# issues

Tickets for work on adtb: the engine, the front end (`adtb-lang`), the
reference interpreter, the simulator, tooling and the docs. Design
decisions are never tickets. They live in the quandary space under
`work/research/`; a ticket that needs a ruling says so and waits for it.
Check here before treating a gap as permanent, and file a ticket when
you hit one rather than working around it quietly.

Tickets live directly in this directory and never move. Query and update
them with `tix` (`tix help`). Until `tix` is on PATH in devenv
([`tix-in-devenv.md`](tix-in-devenv.md)), run it from the repository
root as:

```
nix run path:/home/tony/code/tql/work/tools/tix -- -C work/issues <cmd>
```

```
tix list --ready                         # open, every dependency resolved
tix deps <stem> [--reverse]              # what it needs, or what needs it
tix new <stem> --kind feature --summary "..."
tix close <stem> resolved
tix check                                # fields, links, dependencies, index
```

## Format

One file per ticket, named for the gap. YAML frontmatter, one field per
line:

```yaml
created-at: 2026-10-25
status: in-progress
kind: feature
priority: 200
summary: "no evaluator for the semantics equations of queries"
branch: interp
closed: 2026-11-02
depends-on: [kernel-writes-contract]
tags: [reference]
```

`status` is `open`, `in-progress`, `resolved` or `wontfix`, and `kind` is
`bug` or `feature`. `branch` is only for in-progress tickets: the name of
the jj workspace the work happens in. `closed` is only for resolved and
wontfix ones. `summary` is the ticket's line in the index below.
`depends-on` names tickets by file stem; `tix` derives what depends on a
ticket. `tix` rewrites the frontmatter, so it keeps no comments. Link a
ticket by its file name.

`priority` orders open tickets, lowest first. It is the milestone of
`docs/plan.md` times 100 plus the order within it: milestone 1 is 100 to
199, milestone 2 is 200 to 299, and so on. A bug that gives a wrong
answer, or lets a wrong program through unchecked, goes below its
milestone's band start (99 for milestone 1). Tooling that every agent
needs sits below 100.

`tags` are drawn from this list; `tix list --tag a,b` keeps tickets with
any of them:

- `lang`: `adtb-lang`, the parser, checker and kernel;
- `reference`: `adtb-reference`, the interpreter and conformance runner;
- `sim`: `adtb-sim`, `adtb-sys` and the runtime interfaces;
- `engine`: the storage engine in `adtb`;
- `spec`: `docs/spec/`;
- `design`: `docs/design/`;
- `test`: test suites, fuzzers and checkers;
- `tooling`: the dev shell, tix, quandary and other tools;
- `milestone`: one ticket per milestone of `docs/plan.md`, depending on
  the tickets that belong to it.

The first section is `## Report`: what is missing or wrong, stated
concretely, a repro where one applies, and the root cause if known. Never
rewrite it. Later work appends a dated `## <date>: <label>` section
saying what changed and what is still open. Closing a ticket appends a
`## <date>: resolved` or `## <date>: wontfix` section saying how or why.

A bug is titled with its symptom; a feature is titled `# Feature:
<what>`. When a repro applies, give the program as a laid-out `adt`
block, the command, and the actual and expected output, each in its own
block:

````
```adt
-- from version 12
add unique (lower(email)) in identities.EmailPass
```

```
cargo test -p adtb-lang --test spec_corpus spec_examples_check
```

Actual:

```
writes.md:590:
  writes.md:592: migration operators are not checked yet
```

Expected: the block checks.
````

The command runs as written from the repository root inside the devenv
shell.
