# SurrealDB

kind: system
home: https://surrealdb.com/docs

## Types

- Base types: `any`, `array`, `bool`, `bytes`, `datetime`, `decimal`, `duration`, `float`, `geometry`, `int` (64-bit signed), `number`, `object`, `range`, `regex`, `record`, `set`, `string`. [V 2026-10-25] https://surrealdb.com/docs/surrealql/datamodel
- Union types written `string | int`; `option<T>` is sugar for `T | NONE`; `record<table>` restricts a record id to given tables. [V 2026-10-25] https://surrealdb.com/docs/surrealql/datamodel
- Literal types act as enums and tagged unions, including object literals: `{ Continue: { message: "" } } | { Retry: { error: "Retrying", after: duration } } | { Deprecated: { message: string } }` or a shared discriminant field `{ error: "Continue" } | { error: "RetryWithId", id: string }`. [V 2026-10-25] https://surrealdb.com/docs/surrealql/datamodel/literals
- No `match`/`switch`: docs say literals are matched with `IF ELSE` on field truthiness (`IF $err.Continue`); no exhaustiveness check. Unions are structural checks on a document, not a stored tag. [V 2026-10-25] https://surrealdb.com/docs/surrealql/datamodel/literals

## Records and links

- Record id is `table:id`; id may be text, int, array, object, or generated by `rand()` (20-char default), `ulid()`, `uuid()`. Ids are immutable after creation. [V 2026-10-25] https://surrealdb.com/docs/surrealql/datamodel/ids
- Ids sort by kind then value: numbers, strings, arrays (elementwise), objects. Range queries `person:1..1000`, `temperature:['London', NONE]..=['London', ..]` scan the key range with no table scan. [V 2026-10-25] https://surrealdb.com/docs/surrealql/datamodel/ids
- A `record<author>` field accepts the id of a record that does not exist; existence needs `ASSERT record::exists($value)`. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/define/field
- `DEFINE FIELD ... REFERENCE` on a top-level record (or array of records) field enables reverse traversal `<~(person FIELD comics)` and `ON DELETE IGNORE | UNSET | CASCADE | REJECT | THEN`; default `IGNORE` keeps broken references. [V 2026-10-25] https://surrealdb.com/docs/surrealql/datamodel/references
- `RELATE @from -> @edge_table -> @to` creates an edge record in its own table with `in`/`out` fields; traversal `->`, `<-`, `<->`; edges may point to edges; recursive traversal up to 256 levels. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/relate

## Schema

- `DEFINE TABLE ... SCHEMAFULL` rejects undeclared fields ("Found field 'X', but no such field exists for table 'Y'"); `SCHEMALESS` accepts extras but still validates declared fields. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/define/table
- `DEFINE TABLE ... TYPE ANY | NORMAL | RELATION [IN t] [OUT t] [ENFORCED] [LIGHTWEIGHT]`: `ENFORCED` blocks `RELATE` unless endpoints exist; `LIGHTWEIGHT` edges carry no properties, identity is the `[in, out]` pair. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/define/table
- `DEFINE FIELD` clauses: `TYPE`, `FLEXIBLE` (allow undeclared keys in object fields on SCHEMAFULL tables), `ASSERT` (boolean over `$value`), `VALUE` (runs on every write to the record, not only writes setting the field), `DEFAULT` (CREATE only), `DEFAULT ALWAYS` (also UPDATE when NONE), `READONLY`, `REFERENCE`, `OVERWRITE` / `IF NOT EXISTS`. Nested fields typed by path `field.name`, `field[0]`, `field.*`. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/define/field
- Defining a field never validates existing data: "Defining a field does not change the records already in the table. The clauses apply the next time each record is written." [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/define/field
- `DEFINE TABLE x AS SELECT ...` makes a read-only materialized view, "event-based, incrementally updating" from source table events after a first full run. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/define/table
- `ALTER` modifies tables, fields, indexes, sequences, functions, analyzers, events and more, giving only changed clauses, e.g. `ALTER TABLE user SCHEMAFULL`; docs do not say whether existing data is checked. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/alter
- `CHANGEFEED @duration [INCLUDE ORIGINAL]` on a table keeps a change log read by `SHOW CHANGES FOR TABLE`. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/define/table

## Indexes

- Index kinds: standard (non-unique), `UNIQUE` (multiple null/missing allowed), composite, `COUNT [WHERE cond]`, `FULLTEXT` with analyzers and BM25-style scoring, vector `HNSW` (in memory), `DISKANN` (since 3.1.0), brute force. `CONCURRENTLY` builds in background. [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/define/indexes

## Storage and key encoding

- Query layer sits on a key-value contract: "transactional read and write of individual keys and key ranges. That is the whole contract". Document, its edges and its index entries are written in one transaction to one store. [V 2026-10-25] https://surrealdb.com/docs/surrealdb/introduction/architecture
- Key layout: record `/*{ns}*{db}*{tb}*{id}`; graph edge entry `/*{ns}*{db}*{tb}~{id}{eg}{ft}{fk}`; reference `/*{ns}*{db}*{tb}&{id}{ft}{ff}{fk}`; index entry `/*{ns}*{db}*{tb}+{ix}*{fd}{id}`; table catalog `/*{ns}*{db}!tb{tb}`, field defs `...*{tb}!fd{fd}`; change feed `/*{ns}*{db}#{ts}*{tb}`. All records of one table share one prefix. [V 2026-10-25] https://github.com/surrealdb/surrealdb/blob/main/surrealdb/core/src/key/mod.rs
- Engines in source tree: mem (SurrealMX), RocksDB, SurrealKV, TiKV, IndexedDB. FoundationDB removed by commit "Remove FoundationDB storage engine (#6578)". [V 2026-10-25] https://github.com/surrealdb/surrealdb/tree/main/surrealdb/core/src/kvs
- RocksDB backend uses `OptimisticTransactionDB` with snapshots set per transaction. TiKV backend chooses optimistic or pessimistic transactions and rejects versioned queries (`UnsupportedVersionedQueries`). [V 2026-10-25] https://github.com/surrealdb/surrealdb/blob/main/surrealdb/core/src/kvs/rocksdb/mod.rs
- SurrealKV: LSM tree (WAL, SSTables, value log with WiscKey separation above 1 KiB, manifest), MVCC, OCC commit pipeline, snapshot isolation, optional versioning with retention and `get_at(key, ts)`. [V 2026-10-25] https://github.com/surrealdb/surrealkv
- `SELECT ... VERSION <datetime>` time travel only on engines with versioning enabled (RocksDB, SurrealKV). [V 2026-10-25] https://surrealdb.com/docs/surrealql/statements/select

## Transactions

- Each statement runs in its own transaction unless grouped by `BEGIN` ... `COMMIT` / `CANCEL` inside one query; no nesting (an inner `BEGIN` aborts the outer); cannot span HTTP requests. [V 2026-10-25] https://surrealdb.com/docs/surrealql/transactions
- "Every transaction runs under snapshot isolation with write conflict detection on commit, whichever storage backend sits underneath." [V 2026-10-25] https://surrealdb.com/docs/surrealdb/introduction/architecture
